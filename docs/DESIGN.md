# Генератор нагрузки и журнал исходов

Часть роли A: нагрузка с управляемой конфликтностью и журнал каждой попытки транзакции.
Журнал читают чекер сериализуемости (роль C) и обработка метрик (роль B).

## Нагрузка

Логическая транзакция выбирает `k` разных ключей из горячего множества размера `H`
(равномерно, генератор `PCG(seed, client)`), читает их и пишет в каждый одно и то же
значение `<txn>/<attempt>`. Значение уникально для попытки, поэтому по прочитанному значению
однозначно видно, какая попытка какой транзакции его записала. Конфликтность задается `H`
при фиксированных `k` и числе клиентов. Перед запуском диапазон ключей очищается, начальное
состояние пустое.

Клиенты работают параллельно, каждый выполняет транзакции последовательно до конца
длительности запуска. Попытка ограничена таймаутом транзакции FDB.

## Журнал

JSONL, одна строка на попытку:

| Поле | Смысл |
|---|---|
| `txn` | id логической транзакции, `c<client>-<seq>` |
| `attempt` | номер попытки с 1 |
| `client` | номер клиента |
| `start_ns`, `end_ns` | время начала и конца попытки, unix ns |
| `read_version` | read version попытки, 0 если не получена |
| `commit_version` | commit version, только для `committed` |
| `reads` | `[{"k":..., "v":...}]`, `v` отсутствует, если ключа нет |
| `writes` | `[{"k":..., "v":...}]`, пустой, если попытка оборвалась до записи |
| `outcome` | `committed`, `conflict`, `unknown`, `aborted` |
| `error` | код ошибки FDB, 0 для `committed` |
| `snapshot` | чтения шли через snapshot и не регистрировали конфликтов |

Исходы:

- `committed`: коммит подтвержден.
- `conflict`: коммит отклонен с 1020 `not_committed`, записи точно не применены.
- `aborted`: ошибка до отправки коммита или 1007 на коммите, записи точно не применены.
- `unknown`: любая другая ошибка коммита (1021, таймаут 1031 и прочие). Записи могли
  примениться. До основной серии будет добавлен атомарный marker попытки: он разрешит
  исход как applied/not applied, а неразрешимый случай даст `inconclusive`.

## Сводка метрик

`cmd/summary` считает число логических транзакций и попыток, conflict rate, долю
подтверждённых транзакций с повтором, среднее число дополнительных попыток, throughput,
средний параллелизм попыток и p50/p95/p99 сквозной задержки подтверждённых транзакций.
Средний параллелизм равен сумме длительностей попыток, делённой на окно журнала.

## Поведение (каждая строка соответствует тесту)

| Тест | Поведение |
|---|---|
| `TestNewWorkload_RejectsBadSizes` | `H < 1`, `k < 1` или `k > H` дают `ErrInvalidWorkload` |
| `TestWorkloadPick_DistinctKeysInsideHotSet` | `Pick` возвращает `k` разных ключей из `H`, отсортированных |
| `TestWorkloadPick_SameSeedSameKeys` | одинаковый seed дает одинаковую последовательность ключей |
| `TestTxnSpec_ValueUniquePerAttempt` | значения разных попыток и транзакций различаются |
| `TestOutcome_Committed` | только `committed` значит, что записи применены |
| `TestRunLoad_JournalsEveryAttempt` | каждая попытка, о которой сообщил исполнитель, попадает в журнал |
| `TestRunLoad_TxnIDsUnique` | id логических транзакций не повторяются между клиентами |
| `TestRunLoad_StopsWhenContextEnds` | по истечении контекста клиенты останавливаются, ошибки нет |
| `TestRunLoad_FailsOnJournalError` | ошибка журнала останавливает запуск и возвращается |
| `TestRunLoad_FailsOnRunnerError` | неповторяемая ошибка исполнителя останавливает запуск |
| `TestSummarize_KnownHistory` | сводка на истории с известным ответом: доли, повторы, параллелизм и перцентили |
| `TestJournal_RoundTrip` | запись и чтение JSONL сохраняют все поля |

## Предположения

- Ошибки FDB, кроме 1020 и 1007, во время коммита считаются `unknown`; до внедрения marker
  такие исходы нельзя использовать для окончательного pass чекера.
- Задержка логической транзакции считается от начала первой попытки до конца успешной.
- Перцентили считаются методом nearest-rank.
